Fluxo

Como é hoje vs. como ficaria com CISa

Hoje — OMIE

  1. Financeiro gera arquivo CNAB no OMIE.
  2. Arquivo é transmitido ao Santander pelo fluxo já conhecido.
  3. Santander processa e devolve arquivo de retorno (.txt).
  4. OMIE lê o retorno e faz baixa automática.

Proposto — NetSuite + CISa

  1. NetSuite gera arquivo e salva na pasta OUTBOX (monitorada pela CISa).
  2. CISa/AFT transmite automaticamente ao Santander a cada 15 minutos.
  3. Santander processa e devolve arquivo de retorno na pasta INBOX.
  4. NetSuite lê o arquivo de retorno e realiza a baixa.

Validações com Santander

Status das perguntas em aberto

⏳

A CISa pode coexistir com o fluxo atual do OMIE sem qualquer impacto?

Aguardando resposta do Santander

ℹ

O layout do arquivo de retorno será CNAB padrão ou específico para o NetSuite?

".RET" é a extensão do arquivo de retorno, não um formato CNAB específico

A ser validado: qual formato exato o NetSuite espera ler do arquivo de retorno.

✓

Existe custo adicional de contratação, implantação, manutenção ou suporte?

Não — sem custo adicional confirmado pelo Santander

✓

Qual o SLA do Santander para falha de transmissão ou indisponibilidade?

Agendamento a cada 15 minutos (configurável no Agendador de Tarefas do Windows)

Frequência parametrizável — não há SLA formal de suporte declarado pelo banco.

✓

Se a CISa falhar, podemos transmitir/baixar arquivos manualmente?

Sim — o internet banking continua disponível normalmente como fallback

CISa é um meio adicional de transmissão, não o único. Em caso de falha, o fluxo manual via internet banking segue operando.

✓

As instalações podem ser em notebook? Quais os requisitos?

Sim — manual de instalação recebido (Windows 64 bits, porta 9000, instalação como administrador)

Recomendamos servidor dedicado para maior estabilidade, mesmo que notebook seja tecnicamente viável.

Requisitos Técnicos

O que a CISa exige para funcionar

🖥️ Requisitos mínimos

  • Windows 64 bits (notebook ou servidor)
  • Processador 1 GHz ou superior
  • 256 MB de memória livre
  • 200 MB de disco + espaço para logs
  • Porta 9000 liberada no firewall
  • Executar instalação como Administrador

🔐 Configurações obrigatórias

  • Modo de operação: Automático
  • Caixa de entrada e saída: código GE (enviado por e-mail pelo Santander)
  • Ativação do Token: usuário + código de ativação
  • Senha: 8+ caracteres, maiúscula, minúscula e especial
  • Tarefa agendada: repetição a cada 15 minutos

🔗 URLs de conexão Santander

  • cisa.santander.com.br/cisa/asl/ASLIntegration
  • cisa.santander.com.br/cisa/asl/AFTServlet
  • Testar conectividade via CMD (ping / tracert) antes de instalar

📋 Arquivos de LOG

  • aftservice-0-0.log
  • AFTClient_Config.xml
  • Em caso de erro, encaminhar ao Santander com esses arquivos anexos
  • Local: C:\Program Files\Santander ASL Automated File Transfer

Estrutura de diretórios — C:\Santander\AFTData

📤 OUTBOX
Envio dos arquivos remessa para o Santander
📥 INBOX

✅ SENTBOX

❌ ERRORBOX

📋 LOGBOX

Próximos Passos

Roteiro de homologação

1

Confirmar coexistência com OMIE

Única pendência ainda em aberto com o Santander. Não iniciar instalação antes dessa confirmação.

2

TI liberar porta 9000 e validar conectividade

Testar acesso às URLs do Santander via CMD (ping/tracert). Pré-requisito antes de qualquer instalação.

3

Instalar CISa em máquina Windows 64-bit

Executar como Administrador. Configurar modo automático, caixas GE de entrada/saída e ativar Token com senha válida.

4

Configurar Agendador de Tarefas (15 minutos)

Ajustar data de início e repetição. Monitorar logs após primeiro ciclo de execução.

5

Validar formato do arquivo de retorno com NetSuite

Confirmar com a consultoria NetSuite qual formato e extensão são esperados para que a baixa funcione corretamente.

6

Homologar em paralelo — sem desligar OMIE

Testar pagamento, cobrança, retorno, rejeição e baixa ponta a ponta. Fallback via internet banking disponível em caso de falha.

7

Definir governança e go-live

Financeiro opera; TI sustenta a máquina; Santander suporta a conexão. Manter OMIE e internet banking como contingência.

Conclusão

Leitura executiva para decisão

Risco operacional menor do que o esperado.
A CISa é um meio adicional de transmissão — em caso de falha, o internet banking segue disponível. Não há risco de ruptura total do fluxo de pagamentos.

Uma pendência e um ponto técnico a resolver.
Confirmar coexistência com OMIE (Santander) e validar o formato do arquivo de retorno esperado pelo NetSuite (consultoria) antes do go-live.

Sem custo e com fallback garantido.
A implementação é gratuita e o internet banking serve como contingência imediata. Homologar em paralelo com OMIE ativo é a abordagem recomendada.
